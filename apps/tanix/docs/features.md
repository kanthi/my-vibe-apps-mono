# What each Tanix system includes

Added 2026-11-17. **Evaluated, not yet install-tested**: every installer choice and the live ISO produce a valid configuration (`./scripts/check-desktops.sh`), and the wallpapers build. Nothing below has been seen running in a VM yet.

All of it lives in `modules/tanix/`, which the installer copies to `/etc/nixos/tanix` on every installed system. The installer itself only writes a few `tanix.*` lines into `configuration.nix`.

## Every system (`base.nix`)

| Feature | Detail | Switch off with |
| --- | --- | --- |
| Command-line tools | git, curl, wget, htop, btop, ripgrep, fd, jq, tree, file, unzip, zip, vim, helix, fastfetch | `tanix.base.enable = false;` (turns off the whole base) |
| Flakes | `nix-command` and `flakes` switched on | same |
| Clean-up | weekly removal of system generations older than 14 days, plus store de-duplication | same |
| zram | compressed swap in RAM | same |
| Shell | zsh with the starship prompt for every user; fastfetch on login shells (set `TANIX_NO_FASTFETCH=1` to skip) | same |
| Automatic upgrades | nightly at 04:00 (random delay up to 45 min) from the NixOS channel, never reboots by itself | `tanix.autoUpgrade.enable`: the installer writes `true` for servers, `false` for desktops |

## KDE Plasma (`plasma.nix`, plus the layout in `default.nix`)

- Tanix wallpaper on the **SDDM login screen** (Breeze theme override) and the **lock screen**.
- Tanix blue as the Plasma **accent colour** (`tanix.branding.accentColor`), on stock Breeze.
- **Tanix icon themes**: Tanix Minimal 3D is the default, Tanix Minimal (flat) is installed alongside; both cover the everyday apps and fall back to Breeze. Option `tanix.desktop.iconTheme` (`tanix-minimal-3d`, `tanix-minimal`, `breeze`). Applies to every Plasma system: the live session, KDE Plasma and the Security Edition.
- Extra apps: KCalc, Filelight, KDE Partition Manager. Plasma already brings Konsole, Dolphin, Kate, Ark, Gwenview, Okular and Spectacle; the installer adds Firefox.
- **Flatpak with Flathub**, browsable in Discover (Plasma adds Discover when Flatpak is on). A one-shot service adds the Flathub remote once the network is up.
- Switches: `tanix.desktop.extras.enable` (apps and Flatpak), `tanix.desktop.extras.flatpak`. The live ISO has Flatpak off.

## Hyprland (`hyprland.nix`, configs in `assets/hyprland/`)

- A full Tanix `hyprland.conf`: gaps, rounding, blur, animations, Tanix border colours.
- Waybar in Tanix colours (workspaces, window title, clock, volume, network, battery, tray).
- hyprlock with the Tanix wallpaper; hypridle locks after 5 minutes and turns the screen off after 10.
- mako notifications; cliphist clipboard history; grim/slurp screenshots.
- Keys (Super = Windows/Command key):

| Keys | Action |
| --- | --- |
| Super+Return | terminal (kitty) |
| Super+Space | app launcher (hyprlauncher) |
| Super+E | file manager (Dolphin) |
| Super+Q | close window |
| Super+F / Super+T | fullscreen / floating |
| Super+L | lock |
| Super+V | clipboard history |
| Print / Shift+Print | screenshot of an area / the whole screen, to the clipboard |
| Super+1..9, Super+Shift+1..9 | go to / move window to workspace |
| Super+arrows, Super+Shift+arrows | move focus / move window |
| Super+Shift+E | log out |

How the configs get to the user: Hyprland, Waybar and mako only read the home folder, so a user service (`tanix-hyprland-defaults`) copies the files into `~/.config` at login, only where no file exists yet. Hyprland's own generated placeholder (`autogenerated = 1`) is replaced, because Hyprland may start before the copy; it reloads its config when the file changes.

Login on Hyprland stays SDDM with its stock theme. The Tanix SDDM background needs Plasma's Breeze theme, which a Hyprland system does not have. greetd with tuigreet was the alternative; not done.

## Servers (`server.nix`)

Every server choice:

- SSH with **keys only** (no passwords, no root login), and **fail2ban**.
- `tanix-add-ssh-key github:NAME` (or a URL, or a pasted key) adds keys for the current user. Run it from the console after installing, since SSH has no password login.
- Nightly automatic upgrades.
- Optional, commented out in `configuration.nix`: `tanix.server.tailscale.enable`, `tanix.server.containers.enable`.

| Choice | Adds |
| --- | --- |
| Server: Minimal | only the above |
| Server: Web (Caddy) | Caddy serving `/var/www`, a Tanix welcome page (copied once, never overwritten), ports 80 and 443 open. `tanix-web-setup` asks for a domain and e-mail, writes them to `configuration.nix` and applies. |
| Server: Containers (Podman) | Podman with a docker-compatible `docker` command, DNS between containers, podman-compose |
| Server: Database (PostgreSQL) | PostgreSQL, local connections only. Start with `sudo -u postgres psql`. |

The domain and e-mail could not go into the installer: Calamares's System page has no text fields. `tanix-web-setup` after the install is the replacement.

## Security Edition (`security.nix`)

Decided 2026-11-17: start from KDE Plasma cut down to a minimal base; add tools later, per category, the way Kali's menu groups them.

- **Minimal Plasma**: no Elisa, Gwenview, Okular, KHelpCenter, KRdp, browser integration, extra wallpapers, on-screen keyboard, video thumbnails, Dolphin plugins. No screen reader, no KDE PIM, no file indexing (Baloo), no printing, no Flatpak or extra apps. Kept: Konsole, Dolphin, Kate, Ark, Spectacle, Firefox.
- **Hardening**: AppArmor on; random MAC address on Wi-Fi and Ethernet; no SSH server.
- **Look**: a red version of the dark wallpaper and a red accent colour.
- **Tools**: 13 categories, all empty for now:

| Option (`tanix.security.categories.<name>`) | Kali menu entry |
| --- | --- |
| `information-gathering` | Information gathering |
| `vulnerability-analysis` | Vulnerability analysis |
| `web-application` | Web application analysis |
| `database-assessment` | Database assessment |
| `password-attacks` | Password attacks |
| `wireless-attacks` | Wireless attacks |
| `reverse-engineering` | Reverse engineering |
| `exploitation` | Exploitation tools |
| `sniffing-spoofing` | Sniffing and spoofing |
| `post-exploitation` | Post exploitation |
| `forensics` | Forensics |
| `reporting` | Reporting tools |
| `social-engineering` | Social engineering tools |

Each category has `packages` (a list) and `enable` (default `true`, to drop a whole category). `tanix.security.extraPackages` takes tools that fit no category. Tools that do not build for the machine's CPU are skipped rather than failing the install.

## Live ISO (`modules/iso.nix`)

- The live user is `tanix` (was `nixos`). The stock user is switched off; autologin, console login, help text and Nix's trusted users point at `tanix`.
- The live desktop shows only "Install System" and GParted; the "NixOS Manual" icon is gone.
